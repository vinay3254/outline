# Cutline v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local-first browser editor that imports local video, makes non-destructive frame-quantized edits, previews filters, and exports a composed file.

**Architecture:** React owns the progressive hybrid workspace and renders immutable project state. A pure timeline package stores integer-frame records and command history; preview and export consume its resolved sequence without mutating it. Browser media and WebGL handle interactive preview, while an FFmpeg WebAssembly worker provides the first export adapter.

**Tech Stack:** React, TypeScript, Vite, Vitest, Testing Library, Playwright, Zustand, IndexedDB, WebGL2, `@ffmpeg/ffmpeg`.

**Spec:** `docs/superpowers/specs/2026-09-06-cutline-design.md`

## Global Constraints

- Use TypeScript strict mode and immutable project updates.
- Store all edit time as integer frame ticks; new projects default to 30 fps and cannot change frame rate afterward.
- Source files are never changed; clips only reference asset metadata and source intervals.
- Use browser-local data only. Persist metadata in IndexedDB; mark unavailable sources offline rather than replacing them.
- v1 accepts browser-supported MP4/WebM, permits no clip overlap on a track, and resolves one active video clip in preview/export.
- Do not create commits while executing this plan unless the product owner explicitly changes the current instruction.
